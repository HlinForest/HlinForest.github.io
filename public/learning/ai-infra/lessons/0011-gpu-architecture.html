GPU 架构、存储与 Roofline

目标：能把 Kernel 的线程组织、数据访问和算术强度映射到硬件资源，并用测量判断真正瓶颈。

过关标准

  • 能解释 CPU 延迟导向与 GPU 吞吐导向。
  • 能画出 Grid → Block → Warp → Thread 与 SM 的映射。
  • 能比较寄存器、共享内存、L1/L2、HBM 与主机内存。
  • 能解释 coalescing、divergence、occupancy 与 Tensor Core。
  • 能使用 Roofline 形成可验证的性能假设。

1. GPU 用并发隐藏延迟

CPU 用复杂控制、缓存和少量强核心降低单线程延迟；GPU 用大量轻量线程和高带宽提高吞吐。当一个 Warp 等待内存时，SM 可以调度另一个就绪 Warp。

GPU 并不自动适合所有任务。工作必须有足够并行度，并且计算收益能覆盖主机—设备传输与 Kernel 启动。

2. 执行层级

Grid
一次 Kernel 启动
Block
分配给某个 SM
Warp / Thread
32 线程调度组

Block 内线程可通过 shared memory 和 block barrier 协作；不同 Block 默认不能在同一 Kernel 内做全局 barrier。Warp 中线程执行同一指令流，不同分支会分阶段执行，造成 divergence。

3. SM 中的主要资源

  • CUDA Core：通用标量/向量算术流水线。
  • Tensor Core：矩阵乘累加单元，支持特定 dtype 和 tile。
  • 寄存器：每线程最快存储，数量有限。
  • Shared Memory/L1：SM 内低延迟共享与缓存。
  • Warp Scheduler：从就绪 Warp 中发射指令。

每个 Block 使用的线程、寄存器和 shared memory 共同决定一个 SM 能同时驻留多少 Block/Warps。

4. 存储层次

层级作用域工程特征
寄存器线程私有最快；过多会降低 occupancy 或 spill
Shared MemoryBlock程序员管理；适合 tile 复用与协作
L1/L2SM / 全卡硬件缓存；命中依赖局部性
HBM全卡容量大、带宽高，但远慢于片上存储
主机内存CPU经 PCIe/NVLink-C2C 等链路传输

5. 三个常见效率损失

  1. 不合并访问：相邻线程访问分散地址，产生更多内存事务。
  2. Warp divergence：同一 Warp 走不同分支，部分线程空转。
  3. 资源过量：每线程寄存器或每 Block shared memory 太多，减少同时驻留的 Warp。

高 occupancy 不等于高性能。只要已有足够 Warp 隐藏延迟，继续追 occupancy 可能伤害寄存器复用和指令效率。

6. Tensor Core 与低精度

Tensor Core 对规则矩阵 tile 做高吞吐乘累加。获得峰值需要匹配 dtype、尺寸、对齐、布局与库路径。低精度提高理论算力和有效带宽，但必须配合高精度累加、缩放与误差验证。

7. Roofline 诊断

Arithmetic intensity = FLOPs / bytes
Attainable FLOP/s = min(Peak FLOP/s, AI × Memory BW)
  1. 先算或测 FLOPs 与字节数。
  2. 与硬件峰值带宽、峰值算力比较。
  3. 低 AI：优先复用、融合、减少中间写回。
  4. 高 AI 但低利用：检查 tile、并行度、Tensor Core、occupancy 和指令。
  5. 用 profiler 验证，不把 Roofline 当结论。

8. 架构演进只记动机

代际前置阶段应记住
VoltaTensor Core 与独立线程调度成为 AI 时代的重要起点
Turing低精度推理能力增强
AmpereTF32、BF16 与稀疏 Tensor Core 扩展训练路径

不要死背峰值规格；学习任务是理解新架构在计算、内存、精度或通信的哪一侧改变了约束。

9. 拓扑决定并行映射

机内 PCIe、NVLink、NVSwitch 与机间 InfiniBand/RoCE 的带宽和延迟不同。通信量大的张量并行通常更依赖高带宽机内链路；跨机更适合通信频率或体量相对可控的维度。
