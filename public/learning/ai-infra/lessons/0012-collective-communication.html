集合通信与 NCCL

目标：能画出每种 collective 的数据流，估算 Ring/Tree 成本，并用拓扑与时间线解释多卡扩展效率。

过关标准

  • 能解释 rank、world size、process group 与点对点通信。
  • 能区分 Broadcast、Reduce、AllReduce、AllGather、ReduceScatter、AllToAll。
  • 能推导 Ring AllReduce 每 rank 通信量。
  • 能比较 Ring 与 Tree 的带宽/延迟权衡。
  • 能解释 NCCL、RDMA、拓扑和计算通信 overlap。

1. 分布式基本坐标

  • rank：进程在通信组中的编号。
  • world size：组内进程数。
  • process group：参与某组 collective 的 ranks。
  • backend：执行通信的实现；GPU 场景常用 NCCL。

Send/Recv 是定向的一对一积木；Collective 是组内所有 rank 以相同语义共同参与的操作。

2. Collective 语义

原语输入/输出直觉典型用途
Broadcast一个 rank 的数据复制给所有 rank初始化、配置
Reduce所有输入归约到一个 rank聚合到根
AllReduce归约结果发送给所有 rank数据并行梯度
AllGather每个 rank 的分片拼到所有 rank收集参数/激活分片
ReduceScatter先归约，再把结果分片给各 rank分片梯度或参数
AllToAll每个 rank 向每个 rank 发送不同分片MoE token 路由

3. 延迟—带宽模型

通信时间 ≈ steps × α + bytes × β

α 是每轮启动/网络延迟，β 是每字节时间。小消息更受 α 支配；大消息更受带宽支配。比较算法时必须同时看轮数与字节量。

4. Ring AllReduce

把 M 字节数据切成 N 份，分两阶段：

  1. ReduceScatter：N-1 轮，每轮发送 M/N，并累加收到的块。
  2. AllGather：N-1 轮，每轮发送 M/N，收集所有归约块。
每 rank 通信量 = 2(N-1)/N × M
通信轮数 = 2(N-1)

N 很大时字节量趋近 2M，带宽效率好；但轮数线性增长，因此小消息和大规模 rank 下延迟可能较差。

5. Tree AllReduce

树形归约再广播，轮数约 O(log N)，对小消息和延迟敏感场景更有优势。缺点是链路负载可能不如 Ring 均匀，大消息带宽利用取决于具体树和拓扑。

选择更匹配
Ring大消息、带宽主导、链路均衡
Tree小消息、延迟主导、rank 较多

6. NCCL 做了什么

NCCL 提供 GPU collective，识别 PCIe/NVLink/NVSwitch/网络拓扑，选择通道、协议和算法，并与 CUDA stream 协作。它不会消除糟糕拓扑、错误消息粒度或不一致调用顺序。

NCCL_DEBUG=INFO
NCCL_DEBUG_SUBSYS=INIT,GRAPH,NET
nvidia-smi topo -m

所有 rank 必须以兼容顺序参与 collective；某个 rank 跳过或 shape 不一致，可能导致 hang 而不是漂亮报错。

7. RDMA 与网络路径

RDMA 允许网卡直接读写注册内存，减少 CPU 参与与复制。InfiniBand 原生支持 RDMA；RoCE v2 在以太网上承载 RDMA，需要正确的拥塞控制与无损网络配置。上层性能仍受 GPU Direct、NIC 亲和性、NUMA 与交换拓扑影响。

8. 计算通信 Overlap

只要梯度块已经计算完成，就可以在其他层继续 backward 时异步 AllReduce。有效 overlap 需要：

  • 足够大的独立计算窗口。
  • 合适 bucket 大小：太小启动开销大，太大启动太晚。
  • 独立 stream 与正确依赖。
  • 计算和通信不会争用同一瓶颈资源到互相拖慢。

判断是否 overlap 必须看时间线，不能只因为代码用了 async API 就宣布成功。

9. 通信诊断顺序

  1. 单卡正确性与性能基线。
  2. 同机两卡，确认进程与 device 映射。
  3. 查看拓扑和 NCCL 初始化日志。
  4. 用 nccl-tests 测链路基线，比较 algbw 与 busbw。
  5. 检查消息大小分布与 collective 调用次数。
  6. 查看时间线中的等待、串行和 overlap。
  7. 再调算法、协议、bucket 和进程/NIC 亲和性。

实验：Collective 模拟器

  1. 运行 collectives_lab.py。
  2. 用四个 rank 的列表模拟 Broadcast、AllGather、ReduceScatter 与 AllReduce。
  3. 逐轮打印 Ring ReduceScatter 和 AllGather 的块移动。
  4. 用 α-β 模型比较 Ring/Tree 在小消息与大消息下的时间。
