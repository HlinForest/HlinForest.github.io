1. 对象模型：Python 变量不是盒子

Python 中赋值的核心是“名字绑定到对象”。对象具有身份、类型和值；可变对象的值可以原地改变。is 比较身份，== 比较值。

a = [1, 2]
b = a
b.append(3)
assert a == [1, 2, 3]
assert a is b

def mutate(xs):
    xs.append(4)      # 修改同一个对象

def rebind(xs):
    xs = [99]         # 只改变局部名字

函数参数同样是一次名字绑定。这个模型可以统一解释参数传递、缓存污染、Tensor 原地操作和多线程共享对象。

四个高频陷阱

陷阱根因稳妥做法
默认参数 []定义时只创建一次默认用 None，函数内创建
浅拷贝嵌套容器只复制外层引用明确所有权；确需独占时深拷贝

2. 协议比继承更重要

Python 数据模型通过特殊方法定义协议：__iter__ 让对象可迭代，__len__ 接入 len，__enter__/__exit__ 接入 with。框架大量依赖这种“按能力工作”的设计。

class Batch:
    def __init__(self, samples):
        self.samples = samples
    def __len__(self):
        return len(self.samples)
    def __iter__(self):
        return iter(self.samples)

类型标注用于静态检查和沟通，不会自动验证运行时类型。公共边界优先标注 Sequence[T]、Iterable[T]、Protocol 等抽象能力。

3. 惰性计算、调用边界与资源边界

生成器

yield 让函数暂停并保留状态。峰值内存通常只与当前批次有关；代价是只能消费一次、异常会推迟到迭代时。

def batches(lines, size):
    batch = []
    for line in lines:
        batch.append(line)
        if len(batch) == size:
            yield batch
            batch = []
    if batch:
        yield batch

装饰器

装饰器适合横切调用边界的行为，如日志、缓存和计时。使用 functools.wraps 保留元信息。

上下文管理器

with 把获取与释放绑定到词法作用域，即使发生异常也执行清理。文件、锁、临时目录、CUDA autocast 都属于资源边界。

from contextlib import contextmanager
from time import perf_counter

@contextmanager
def timer(name):
    start = perf_counter()
    try:
        yield
    finally:
        print(name, perf_counter() - start)

4. 并发模型选择

任务首选主要成本
网络、磁盘、小文件 I/O线程或 asyncio锁、阻塞调用卡住事件循环
纯 Python CPU 循环多进程或原生扩展进程启动、序列化、数据复制
NumPy/PyTorch/CUDA底层线程池/GPU，Python 调度同步、Kernel 太碎、数据搬运
大数据跨进程共享内存或增大任务粒度pickle 与 IPC 吞掉收益

常见 CPython 构建中的 GIL 限制同一进程内并行执行 Python 字节码，但阻塞 I/O 和许多原生扩展会释放 GIL。结论不是“线程没用”，而是先识别真正执行工作的层。

CUDA 与 fork：不要在父进程初始化 CUDA 后随意 fork。遵循框架推荐的启动器与 start method。

5. 性能分析的最低纪律

  1. 先明确指标：端到端吞吐、单请求延迟还是某函数耗时。
  2. 预热，重复多次，报告中位数和分布。
  3. 把初始化、I/O 与核心计算分开测。
  4. GPU 工作通常异步；需要 GPU Event 或边界同步。
  5. 只优化 profiler 证实的热点。
python -m timeit -s "xs=list(range(1000))" "sum(xs)"
python -m cProfile -s cumulative script.py
