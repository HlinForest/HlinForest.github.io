自回归生成与 KV Cache

目标：理解一次 LLM 请求在 Prefill 与 Decode 中经历什么，并能计算 KV Cache 与关键性能指标。

过关标准

  • 能解释 next-token prediction 与自回归循环。
  • 能比较 greedy、temperature、top-k 与 top-p。
  • 能区分 Prefill 与 Decode 的并行度和瓶颈。
  • 能推导 KV Cache 大小。
  • 能区分 TTFT、TPOT、端到端延迟和吞吐。

1. 自回归循环

  1. Tokenizer 把 prompt 变成 token IDs。
  2. 模型输出最后位置对词表的 logits。
  3. 采样得到下一个 token。
  4. 把新 token 追加到上下文。
  5. 重复，直到停止条件。
P(x₁…xₜ) = Πᵢ P(xᵢ | x₁…xᵢ₋₁)

2. 采样策略改变质量，不改变模型权重

策略行为权衡
Greedy每步取最大概率确定、快，可能重复和保守
Temperature缩放 logits低温尖锐，高温多样
Top-k只保留概率最高 k 个固定候选数量
Top-p保留累计概率达到 p 的最小集合候选数量自适应

3. Prefill 与 Decode 是两种工作负载

阶段输入并行性常见瓶颈
Prefill整个 prompt序列位置可大规模并行GEMM、Attention 计算、TTFT
Decode每次一个新 token跨请求/批次并行权重与 KV 读取、TPOT

Prefill 往往更 compute-bound；Decode 的矩阵更“瘦”，每步都要读取大量权重与缓存，更容易 memory-bound。

4. KV Cache 为什么存在

历史 token 的 K/V 在每层不会改变。保存后，Decode 只需为新 token 计算 K/V，再与缓存做 Attention，避免重复计算整个前缀。

KV bytes = 2 × L × B × S × Nkv × Dh × bytes_per_element

2 表示 K 和 V，L 是层数。对 MHA，Nkv=Nh；GQA/MQA 通过减少 Nkv 显著降低缓存。

5. KV Cache 算例

32 层、B=1、S=4096、8 个 KV 头、Dh=128、BF16：

2 × 32 × 1 × 4096 × 8 × 128 × 2 bytes = 512 MiB

这只是单个请求。并发请求、长度波动、块管理和碎片会进一步影响服务容量。

6. 推理指标

  • TTFT：请求到首 token，主要受排队、Prefill 和调度影响。
  • TPOT：相邻输出 token 的时间，反映 Decode 体验。
  • 端到端延迟：从请求到全部输出完成。
  • 吞吐：单位时间处理的 token 或请求。
  • 有效利用率：GPU 时间中真正执行有用计算的比例。

批处理通常提高吞吐，但可能增加排队和单请求延迟。生产系统优化不是只追一个数字。

7. 后续优化技术放回瓶颈

技术主要解决
PagedAttentionKV Cache 分配、碎片与共享
Continuous Batching请求动态进入退出，减少空槽
Prefix Cache复用相同前缀 KV
Chunked Prefill限制长 Prefill 对 Decode 的阻塞
Speculative Decoding减少大模型串行 Decode 步数
