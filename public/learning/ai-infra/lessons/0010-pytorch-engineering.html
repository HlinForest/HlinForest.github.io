1. Tensor 操作先看元数据

print(x.shape, x.stride(), x.dtype, x.device)
print(x.is_contiguous())
y = x.permute(0, 2, 1)
z = y.contiguous()  # 明确物化连续副本

view 依赖现有 stride；reshape 可能返回视图，也可能复制。性能审查不能只看输出 shape，还要问是否触发隐式 materialization。

2. Autograd 是动态 DAG

前向执行算子的同时记录梯度函数；backward() 从根沿图反向传播，并把结果累加到叶节点的 .grad。

x = torch.ones(5)
w = torch.randn(5, 3, requires_grad=True)
b = torch.randn(3, requires_grad=True)
loss = (x @ w + b).square().mean()
loss.backward()
print(w.grad, b.grad)
  • 默认梯度累加；每次优化步需 zero_grad()。
  • 图通常在 backward 后释放；重复反传需理解 retain_graph 成本。
  • torch.no_grad() 禁用图记录；detach() 返回共享存储但脱离当前图的视图。
  • 不恰当原地修改可能破坏 autograd 保存的中间量。

3. Module 管理参数与状态

class MLP(torch.nn.Module):
    def __init__(self, hidden):
        super().__init__()
        self.net = torch.nn.Sequential(
            torch.nn.Linear(hidden, 4 * hidden),
            torch.nn.GELU(),
            torch.nn.Linear(4 * hidden, hidden),
        )
    def forward(self, x):
        return self.net(x)

参数必须注册为 Module 属性；可训练参数、持久 buffer 与普通 Python 状态语义不同。state_dict 是参数与 buffer 的映射，不是整个 Python 对象。

4. 标准训练循环

for batch in loader:
    optimizer.zero_grad(set_to_none=True)
    inputs, targets = move_to_device(batch)
    logits = model(inputs)
    loss = criterion(logits, targets)
    loss.backward()
    optimizer.step()

顺序的关键不是形式，而是语义：前向构图，loss 产生标量目标，backward 累加梯度，step 读取梯度更新参数，zero_grad 清理下一步状态。

验证时使用 model.eval() 和 torch.no_grad()：前者改变 Dropout/Norm 行为，后者停止记录梯度，二者不能互相替代。

5. 数据管线与异步搬运

  • num_workers 影响 CPU 数据准备并行度。
  • pin_memory=True 为主机到 GPU 异步 DMA 创造条件。
  • non_blocking=True 只有在内存和 stream 条件满足时才真正异步。
  • 预取过多会增加主机内存和共享内存压力。

不要凭固定数字选择 workers；观察 GPU 空洞、CPU 利用率、队列等待和数据加载时间。

6. 混合精度

with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
    loss = criterion(model(inputs), targets)
loss.backward()
optimizer.step()

BF16 常不需要 GradScaler；FP16 常配合 loss scaling 防止小梯度下溢。Autocast 按算子选择 dtype，不代表所有 Tensor 都变成低精度。数值敏感归约和参数更新通常保留更高精度。

  • 为 backward 保存的激活
  • 临时 workspace 与通信 buffer

8. Profiler 阅读顺序

with torch.profiler.profile(
    activities=[
        torch.profiler.ProfilerActivity.CPU,
        torch.profiler.ProfilerActivity.CUDA,
    ],
    record_shapes=True,
    profile_memory=True,
) as prof:
    with torch.profiler.record_function("train_step"):
        loss = train_step(batch)

print(prof.key_averages().table(sort_by="cuda_time_total"))
现象可能含义下一证据
CPU time ≫ CUDA time数据或 Python 调度DataLoader、调用栈、GPU 空洞
大量短 Kernel启动开销与融合机会调用次数、shape、编译图
频繁 memcpy设备搬运Tensor device、pin/non_blocking
.item() 后空洞隐式同步时间线与调用位置

GPU Kernel 启动异步；普通 CPU 计时若不在边界同步，可能只测到提交时间。

9. 自定义算子边界

自定义算子必须验证 dtype、device、shape、stride、contiguity、边界 shape 和 stream 语义；提供可信参考实现与容差；必要时注册 backward。跨边界的复制与同步必须可见。
