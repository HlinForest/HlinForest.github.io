AI Infra 前置基础：六层知识地图

这一部分不是六门互不相干的课。它训练的是一件事：沿着模型调用链，解释数据如何被表示、计算、执行、搬运和同步。

先记住唯一主线

Python 编排→PyTorch 图与算子→C++ 调度→CUDA Kernel→GPU 数据移动→多卡通信

例如一行 torch.matmul(x, w)，上层是 Python 对象与 Tensor 接口，中间是框架分发和自动微分，下层是矩阵乘法 Kernel；扩展到多卡后，还会引入梯度或参数的集合通信。AI Infra 的核心能力，是能在这条链上指出“哪一层出了什么问题”。

六章各自回答什么

01 · 编程语言与 Linux

程序如何表达并被装载？

Python 关注对象、引用、协议和并发；C++ 关注内存、生命周期、ABI 与编译链接；Linux 负责进程、权限、动态库和环境可观察性。

02 · 工程数学

算子是否合法、昂贵且稳定吗？

把公式翻译成 shape、归约维度、FLOPs、访存量、算术强度和数值风险。重点不是证明，而是工程估算。

03 · Transformer

我们究竟在优化什么？

Attention、FFN、归一化、位置编码与 Decoder Block 是优化对象；Prefill、Decode 和 KV Cache 则把模型结构连接到推理系统。

04 · PyTorch

模型如何变成可执行计算？

Tensor 元数据、动态计算图、autograd、Module、训练循环、Profiler 与自定义算子边界把数学模型连接到后端实现。

05 · GPU 硬件

计算为何没有跑满？

SM、Warp、Tensor Core 与存储层次决定吞吐上限。Roofline 用算术强度区分算力瓶颈和带宽瓶颈。

06 · 集合通信

多张卡如何得到一致结果？

AllReduce、AllGather、ReduceScatter 等原语描述数据重排；Ring/Tree、NCCL、拓扑与 overlap 决定通信成本。

把六章压缩成四个检查动作

动作你要问主要依赖
读接口类型、shape、stride、dtype、device、所有权是什么？编程语言、数学、PyTorch
算账本参数、激活、FLOPs、访存、通信各是多少？数学、Transformer、GPU、通信
找瓶颈时间花在 Python、Kernel、内存、同步还是网络？Linux、Profiler、GPU、NCCL
做验证参考实现、容差、边界 shape、版本与拓扑证据够吗？全部六章

三个最容易混淆的边界

逻辑 shape ≠ 物理布局

转置可能只改变 stride 而不复制数据；相同 shape 也可能有不同连续性。正确性看 shape，性能还要看 layout、stride 和访问顺序。

公式 FLOPs ≠ 实际性能

同样的数学结果可能有不同的数据移动量。低算术强度常被带宽限制，高算术强度才更可能接近算力上限；Kernel 启动、同步与边界转换也会进入总时间。

多卡并行 ≠ 免费加速

切分计算会引入参数、激活或梯度同步。必须同时算计算时间、通信量、拓扑带宽和 overlap，不能只用 GPU 数量推断加速比。

检索练习

1. 一个算子结果异常，第一步最合适的是？

2. 算术强度很低的 Kernel 通常首先受什么限制？

3. AllReduce 的核心语义是？

本轮的有形胜利

看到任何 AI Infra 问题，先尝试说出：它位于哪一层；数据的 shape/layout/dtype/device 是什么；主要账本是计算、内存还是通信；用什么工具收集第一份证据。
