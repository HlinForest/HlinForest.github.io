开场检索

为什么不能只报告训练集 loss？请写两个不同原因。

基准答案

第一，训练 loss 只说明对已用于更新参数的数据拟合程度，不能估计未见数据的泛化；第二，模型可能过拟合、数据泄漏或训练/验证分布不同，验证集能提供这些警报。验证集本身也不能反复用于调参后再声称是无偏测试。

从已知规律合成数据

用 y = 0.7x + 0.3 + ε 创建数据。因为真参数已知，我们能验证学习是否真的发生。

import torch
from torch import nn

torch.manual_seed(42)
X = torch.arange(0, 1, 0.02).unsqueeze(1)  # [N,1]
noise = 0.02 * torch.randn_like(X)
y = 0.7 * X + 0.3 + noise                 # [N,1]

split = int(0.8 * len(X))
X_train, y_train = X[:split], y[:split]
X_test, y_test = X[split:], y[split:]

assert X_train.shape == y_train.shape
assert X_test.shape == y_test.shape
现实数据注意：若原数据有时间顺序、同一用户多条记录或群组结构，随意随机切分可能泄漏。本例按 x 顺序切分是为了观察外推，不代表通用最佳方案。

最小模型和实验配置

device = "cuda" if torch.cuda.is_available() else "cpu"

class LinearModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = nn.Linear(1, 1)

    def forward(self, x):
        return self.linear(x)

model = LinearModel().to(device)
X_train, y_train = X_train.to(device), y_train.to(device)
X_test, y_test = X_test.to(device), y_test.to(device)

loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

训练开始前先记录：

print(model)
print(model.state_dict())
print("parameters:", sum(p.numel() for p in model.parameters()))
print("device:", next(model.parameters()).device)

训练与验证必须分开

epochs = 200
history = {"train_loss": [], "test_loss": []}

for epoch in range(epochs):
    # ----- training -----
    model.train()
    train_pred = model(X_train)
    train_loss = loss_fn(train_pred, y_train)
    optimizer.zero_grad()
    train_loss.backward()
    optimizer.step()

    # ----- evaluation -----
    model.eval()
    with torch.inference_mode():
        test_pred = model(X_test)
        test_loss = loss_fn(test_pred, y_test)

    history["train_loss"].append(train_loss.item())
    history["test_loss"].append(test_loss.item())

    if epoch % 20 == 0:
        print(f"{epoch:03d} train={train_loss.item():.5f} "
              f"test={test_loss.item():.5f}")

读曲线，不只看最后数字

现象可能解释下一步
训练/验证同时下降模型正在学且暂时泛化继续到收敛，检查绝对误差
训练下降，验证上升过拟合或分布差异查泄漏、正则化、数据/容量
两者几乎不动链路 bug、lr 小、模型能力不足检查梯度、参数变化、数据范围
两者剧烈振荡/NaNlr 大、数值不稳、数据异常降 lr，检查 finite、归一化

sanity check：先尝试让模型过拟合极小数据集（例如 8 个样本）。若连小数据都拟合不了，优先怀疑实现/优化，而不是泛化。

Loss 不降时的诊断顺序

  1. 输入和标签是否一一对应，是否包含 NaN/Inf？
  2. shape/dtype/device 是否符合 loss 契约？
  3. 模型输出是否有限、是否随输入变化？
  4. named_parameters() 是否包含预期参数？
  5. backward 后梯度是 None、全零、有限还是爆炸？
  6. step 前后参数是否变化？
  7. 才去调整学习率、模型容量、epoch。
for name, p in model.named_parameters():

出口检查

实验推理

1. train loss 降、test loss 连续升，首先说明？
2. 验证循环最重要的边界之一是？

答案

1：可能发生过拟合（也要检查分布和泄漏）。2：禁止更新参数。
