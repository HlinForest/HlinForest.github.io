真正容易错的是“状态”

你在笔试里常把一次梯度下降写成一行，但程序中的对象会记住状态。把下面四类状态刻进脑中：

参数状态

model.parameters() 中的值会被优化器原地更新；checkpoint 主要保存它们。

梯度状态

parameter.grad 默认累积，不主动清零就会叠加多个 step。

模式状态

model.train() / model.eval() 会改变 Dropout、BatchNorm 等层的行为。

随机状态

初始化、抽样、数据打乱消耗随机数生成器状态；seed 是复现实验的入口，不是绝对确定性的保证。

因此训练代码不能只问“公式对不对”，还要问：当前 tensor 在哪里？是什么 dtype？梯度是否在记录？model 是什么模式？旧梯度清了吗？

第一次执行

import torch

x = torch.tensor([1.0, 2.0, 3.0])
w = torch.tensor([0.1, 0.2, 0.3], requires_grad=True)
score = x @ w
loss = (score - 1.0) ** 2
loss.backward()

print("score:", score.item())
print("loss:", loss.item())
print("gradient dL/dw:", w.grad)

你刚刚已经运行了一个最小计算图：x,w → score → loss。因为 w 需要梯度，autograd 记录运算；backward() 后，w.grad 保存 ∂loss/∂w。

出口检查

闭环检查

1. 反向传播前，防止梯度跨 step 叠加的动作是？
2. loss.backward() 的直接职责是？

答案与理由

1：清空旧梯度。PyTorch 默认累积梯度。2：计算参数梯度；真正修改参数的是 optimizer.step()。
