<p class="lead">收藏资料解决的是“以后可能会看”，学习系统解决的是“下一步做什么、怎样证明已经掌握”。两者的差别，不是笔记更长，而是结构里有没有反馈闭环。</p>

## 从目录改成依赖图

按主题罗列章节很自然，但技能之间往往存在先修关系。例如读分布式训练前，至少要能区分参数、梯度、优化器状态和激活；讨论 FlashAttention 前，要先会核算标准 attention 的中间张量。

因此每一章都应该回答三件事：

- 需要哪些先修对象；
- 学完能完成什么动作；
- 哪个任务可以证明动作已经掌握。

## 让“完成”可以被检查

阅读完成只是过程指标。更好的验收包括：从输入 shape 推导中间张量、复现一个最小实验、解释异常曲线，或在限制条件下做出工程选择。

<Callout type="idea" title="验收模板">
  给定一个未见过的例子，在不查答案的情况下完成推导或实现；再用自动测试、数值不变量或对照实验检查结果。
</Callout>

## 保留错误，而不只是结论

真正能迁移的知识通常来自失败：错误假设是什么、哪个观测推翻了它、修复是否带来新的回归。学习记录如果只保留最终答案，会丢掉最有价值的诊断路径。

一个最小记录可以只有四行：

```text title="learning-log.md"
目标：我要能独立解释并实现什么？
证据：哪个测试、推导或实验说明我做到了？
错误：最初在哪个假设上判断错了？
下一步：当前能力边界还缺哪一块？
```

## 文档是会演化的软件

长期文档需要版本、来源、交叉链接和覆盖检查。概念变化时，应能定位受影响章节；新增材料时，应进入现有知识图，而不是在旁边再造一份平行笔记。

本站的 [学习文档库](/learning/) 会按这个思路维护：课程负责系统覆盖，Blog 负责阶段性观点与可独立阅读的专题。
